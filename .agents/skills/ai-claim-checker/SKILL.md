# AI 주장 검증

자연스럽고 그럴듯한 설명을 사실 확인 없이 학습 근거로 사용하지 않는다.

## 준비

1. [운영 정책](../../../guides/agent/operating-policy.md)과 [범위와 출처 정책](../../../guides/agent/scope-and-source-policy.md)을 읽는다.
2. 검증할 문장, 코드 주석, 다이어그램 또는 자료를 받는다.
3. 현재 주차의 필수 범위에 영향을 주는 주장부터 우선한다.

## 검증 절차

1. 복합 문장을 독립적으로 참·거짓을 판단할 수 있는 최소 주장으로 나눈다.
2. 각 주장을 다음 유형으로 표시한다.
   - 정의 또는 메커니즘
   - 경험적 연구 결과
   - 현재 제품·라이브러리 동작
   - 해석 또는 비유
   - 아직 검증할 수 없는 추측
3. 유형에 맞는 1차 또는 공식 출처를 찾는다.
4. 출처 본문이 주장 전체를 실제로 지지하는지 확인한다.
5. 범위, 버전, 조건이나 예외가 빠졌으면 원래 주장을 좁힌다.

## 상태

각 주장에 하나를 부여한다.

- 확인됨: 출처가 해당 범위의 주장을 직접 지지함
- 조건부: 특정 조건이나 버전에서만 맞음
- 불확실: 적절한 출처를 확인하지 못함
- 반박됨: 신뢰할 수 있는 출처와 충돌함
- 사실 주장 아님: 비유, 의견 또는 학습을 위한 단순화임

출처가 여러 개 있다는 이유로 확인됨을 부여하지 않는다. 같은 내용을 복제한 2차 자료를 독립 근거로 세지 않는다.

## 출력

| 주장 | 상태 | 근거 또는 충돌 | 적용 조건 | 학습 노트 수정안 |
|---|---|---|---|---|

표 아래에 다음을 덧붙인다.

- 현재 학습 완료 조건에 영향을 주는 오류
- 단순화로 유지해도 되는 표현
- 추가 확인이 필요한 내용

학습자의 노트나 진행 기록을 자동 수정하지 않는다. 검증하지 못한 문헌과 링크를 만들지 않는다.
