# 직접 코드 실습

게임 서버 개발 경험은 활용하되 ML·LLM 개념은 처음 배운다는 전제로 구현 과정을 안내한다. 결과물보다 책임, 데이터 흐름과 실패 조건을 설명할 수 있는지를 우선한다.

## 준비

1. [운영 정책](../../../guides/agent/operating-policy.md)을 읽는다.
2. [현재 상태](../../../progress/current-state.md)에서 현재 주차를 확인한 뒤 [과정 안내](../../../curriculum/overview.md)가 연결한 해당 주차 문서에서 학습 목표와 완료 조건만 읽는다. 사용자가 다른 주차를 명시했다면 그 주차를 우선한다.
3. 구현할 범위, 완료 조건, 사용 가능한 시간과 현재 코드를 확인한다.
4. 현재 실습에서 새로 익힐 개념과 이미 익숙한 일반 프로그래밍 요소를 구분한다.

## PEAR 순환

### Plan

코드를 쓰기 전에 학습자가 다음 중 적합한 형태로 구조를 작성하게 한다.

```text
책임 분리
입력과 출력
상태 변화
실패 조건
의사코드 또는 데이터 흐름
```

빠진 책임과 잘못 분리한 책임만 검토한다. 설계를 대신 완성하지 않는다.

### Explore

학습자가 직접 첫 구현을 작성하고 실행하게 한다. 첫 응답에서 완성 코드를 만들거나 파일을 수정하지 않는다. 막히면 `$diagnose-learning-error` 또는 `$progressive-hint-ladder`를 별도로 호출하도록 안내한다.

보조 스킬로 전환하면 현재 PEAR 활동은 중단된다. 돌아올 때 사용자가 `$guided-code-practice`를 다시 호출하고 중단한 PEAR 단계, 보조 뒤 재시도 결과와 사용한 최고 도움 단계를 알려줘야 이어서 진행한다.

### Analyze

실행 후 다음을 설명하게 한다.

- 각 단계가 왜 필요한가?
- 입력이 어떤 변환을 거쳐 출력되는가?
- 어떤 상태가 어디에 저장되는가?
- 어떤 조건에서 실패하는가?
- 테스트가 무엇을 보장하고 무엇을 보장하지 않는가?

실행 결과와 예상이 다르면 결과를 대신 해석하기 전에 학습자의 예상과 원인 추측을 받는다.

### Rewrite

이해하지 못한 생성 코드, 우연히 통과한 부분 또는 설계와 불일치한 부분을 학습자가 수정하거나 다시 작성하게 한다. 모든 코드를 기계적으로 재작성하게 하지 않는다.

## 참고 구현

사용자가 시도와 힌트 이후 참고 구현을 명시적으로 요청하면 제공할 수 있다.

- `참고 구현`과 사용한 AI 도움 수준을 표시한다.
- 현재 학습 범위에 필요한 최소 코드만 제공한다.
- 제공 후 학습자가 구조를 설명하거나 입력·실패 조건을 바꿔 다시 구현하게 한다.
- 참고 구현을 무지원 수행 증거로 취급하지 않는다.

## 종료

```text
직접 구현한 범위
AI 도움을 받은 범위
설명 가능한 책임과 흐름
남은 공백
다음 독립 실습
```

공식 기록이나 코드 파일은 사용자가 별도로 명시하지 않으면 수정하지 않는다.
