# 학습용 코드 리뷰

코드를 대신 고치지 말고 학습자가 스스로 수정할 수 있도록 문제, 근거와 확인 질문을 제공한다.

## 준비

1. [운영 정책](../../../guides/agent/operating-policy.md)을 읽는다.
2. [현재 상태](../../../progress/current-state.md)에서 현재 주차를 확인한 뒤 [과정 안내](../../../curriculum/overview.md)가 연결한 해당 주차 문서에서 학습 목표와 완료 조건만 읽는다. 사용자가 다른 주차를 명시했다면 그 주차를 우선한다.
3. 다음을 확인한다.
   - 학습자가 작성한 설계 또는 의사코드
   - 검토할 코드와 테스트
   - 기대한 동작과 실제 실행 결과
   - 이번 리뷰에서 확인하고 싶은 범위
4. 코드 실행이 필요한 경우 읽기 전용 검사와 테스트만 수행한다. 파일을 수정하지 않는다.

## 검토 순서

1. 학습 목표: 이번 실습이 확인해야 하는 개념이 코드에 드러나는가?
2. 설계 일치: 책임, 입력·출력과 상태 변화가 작성한 설계와 일치하는가?
3. 정확성: 정상 흐름과 현재 범위의 대표 실패가 올바르게 처리되는가?
4. 검증 가능성: 테스트나 재현 절차가 실제 주장을 확인하는가?
5. 설명 가능성: AI가 만든 부분을 포함해 학습자가 각 책임을 설명할 수 있는가?

보안, 성능, 스타일은 현재 학습 목표나 실제 오류와 관련된 경우에만 포함한다. 일반적인 대규모 리팩터링을 제안하지 않는다.

## 발견 사항 형식

중요도 순서로 작성한다.

```text
제목
근거 파일과 위치
현재 동작 또는 위험
학습 목표에 미치는 영향
학습자가 확인할 질문 또는 재현 방법
```

문제가 없으면 없다고 명확히 말하고 남은 검증 한계를 제시한다. 코드 전체를 다시 작성하거나 자동 수정하지 않는다.

## 수정 예시 요청

사용자가 발견 사항을 이해한 뒤 수정 예시를 명시적으로 요청하면 최소 예시를 보여줄 수 있다. 예시는 파일에 적용하지 않으며 학습자의 최종 수정과 설명을 기다린다.

## 종료

- 설계와 일치한 부분
- 반드시 수정할 문제
- 학습자가 다시 확인할 문제
- 테스트 또는 설명으로 재검증할 조건

리뷰 결과를 이해 완료나 공식 진행 상태로 자동 기록하지 않는다.
