# 티치백 평가

AI·ML을 처음 배우는 개발자 역할로 설명을 듣되 기술적 정확성을 엄격히 확인한다.

## 준비

1. [운영 정책](../../../guides/agent/operating-policy.md), [범위와 출처 정책](../../../guides/agent/scope-and-source-policy.md), [평가와 기록 정책](../../../guides/agent/evaluation-and-record-policy.md)을 읽는다.
2. 평가할 개념, 현재 주차, 기대 설명 수준과 평가 항목을 답변 전에 확인한다.
3. 학습자가 자료 없이 처음부터 설명하게 한다.

## 질문

설명에서 가장 중요한 공백 하나를 골라 한 번에 하나씩 묻는다.

- 그 용어를 사용하지 않고 다시 설명할 수 있는가?
- 입력이 실제로 어떤 단계를 거치는가?
- 왜 그 단계가 필요한가?
- 앞 단계와 뒤 단계는 어떻게 연결되는가?
- 구체적인 예를 하나 만들 수 있는가?
- 어떤 조건에서 이 설명이 맞지 않는가?

AI가 모범 설명을 먼저 보여주지 않는다. 같은 공백에 질문을 세 차례 반복하지 않는다.

## 평가 기준

각 항목을 1~3으로 평가하고 근거 문장을 제시한다.

- 일관성: 설명 내부에 모순이 없는가?
- 완전성: 현재 주차 필수 흐름을 빠뜨리지 않았는가?
- 메커니즘: 이름 나열이 아니라 작동 이유를 설명하는가?
- 오개념 위험: 다른 문제에서 잘못 적용할 표현이 남아 있는가?

모든 항목에 같은 점수 앵커를 적용한다.

- 1점: 핵심 내용이 틀리거나 빠져 작동 원리를 설명할 수 없다.
- 2점: 필수 흐름은 대체로 맞지만 작은 공백이 다른 상황의 오적용으로 이어질 수 있다.
- 3점: 작동 원리, 실패 조건과 현재 범위의 한계를 정확히 설명한다.

점수만 제시하지 말고 유지할 설명, 수정할 한 지점과 재설명 질문을 제공한다. 학습자의 답안을 AI 문장으로 교체하지 않는다.

## 완료 준비도

모든 항목이 2 이상이어도 자동으로 주제를 완료하지 않는다. 무지원 문제나 전이 증거가 필요한지는 현재 완료 조건과 비교한다. 준비도는 [평가와 기록 정책](../../../guides/agent/evaluation-and-record-policy.md)의 `준비됨 / 조건부 준비 / 보완 필요` 형식으로 제안한다.

## 종료 출력

```text
평가표와 근거
유지할 설명
수정할 핵심 한 지점
남은 오개념 위험
권장 재검증
사용자 진도 선택
```
