# AI 공통 기반 학습 에이전트 설계

## 1. 목적

이 저장소는 게임 서버 개발 경력자가 AI 포지션 전환에 필요한 공통 기반을 자율 학습하도록 지원한다. AI는 답안 작성 대행자가 아니라 범위 조정자, 질문자, 멘토, 검토자 역할을 맡는다.

학습자는 커리큘럼과 사용자 가이드를 보고 현재 활동을 선택한 뒤 필요한 스킬을 명시적으로 호출한다. AI는 호출된 스킬과 사용자가 선택한 범위 안에서만 행동한다.

## 2. 기준 과정과 범위

- 기준 과정은 `0주차 10시간`과 `1~16주 공통 이해 과정 240시간`이다.
- 0주차와 1~16주차 문서를 과정의 단일 기준으로 사용한다.
- 기존 20주 누적 프로젝트 문서는 현재 과정의 기준에서 제외하고 참고 자료로 보관한다.
- 17~20주 포트폴리오와 선택 프로젝트는 이번 구현 범위에 포함하지 않는다.
- 현재 과정은 이론 이해, 손계산, 마이크로 실험, 독립 미니 과제, 실패 분석과 복습을 다룬다.

## 3. 설계 원칙

1. 학습 에이전트와 교육 스킬은 사용자가 명시적으로 호출해야 작동한다.
2. 학습 범위, 진도, 완료 여부의 최종 결정권은 사용자에게 있다.
3. AI는 준비도와 보완 방향을 제안하지만 다음 단계 진행을 강제로 막지 않는다.
4. 하루 학습 종료와 학습 주제 완료를 구분한다.
5. 하나의 학습 세션은 여러 날에 걸쳐 중단하고 재개할 수 있다.
6. AI는 사용자의 승인 없이 공식 진행 기록을 수정하지 않는다.
7. 도움을 받아 만든 결과와 무지원으로 만든 결과를 구분한다.
8. 핵심 이론은 검증 가능한 출처를 사용하고 사실, 해석, 비유, 추측을 구분한다.
9. 외부 스킬은 필요한 부분만 등록하며 출처와 라이선스를 보존한다.
10. 각 스킬은 하나의 학습 행동을 중심으로 설계한다.

## 5. 문서 소유권과 읽기 규칙

### 5.1 AI가 우선 확인하는 문서

- `AGENTS.md`: 저장소 전체의 강제 규칙과 가이드 진입점
- `guides/agent/operating-policy.md`: AI의 역할과 금지 행동
- `guides/agent/session-state.md`: 세션 상태와 사용자 선택 처리
- `guides/agent/skill-routing.md`: 사용자 목적별 스킬 선택표
- `guides/agent/scope-and-source-policy.md`: 학습 범위와 출처 검증 기준
- `guides/agent/evaluation-and-record-policy.md`: 평가와 기록 반영 조건

AI는 매 요청마다 모든 문서를 읽지 않는다. `AGENTS.md`의 라우팅에 따라 현재 요청에 필요한 문서만 확인한다.

### 5.2 사용자가 우선 확인하는 문서

- `guides/user/start-here.md`: 과정 시작 방법과 전체 지도
- `guides/user/daily-session-guide.md`: 하루 범위 결정, 중단, 재개, 종료 방법
- `guides/user/skill-invocation-guide.md`: 목적별 스킬 호출 예시
- `guides/user/review-guide.md`: 회상, 복습 문제, 무지원 평가 방법
- `guides/user/record-guide.md`: 개인 정리와 공식 진행 기록의 차이
- `curriculum/`: 학습 범위, 주차 목표, 완료 조건

### 5.3 공동 기록

- `progress/`는 사용자가 승인한 공식 진행 상태와 누적 학습 공백을 저장한다.
- `learning-notes/`는 사용자가 직접 작성하는 개인 복습 공간이다.
- AI는 사용자가 요청한 경우에만 개인 노트를 읽거나 검토한다.
- AI가 대화에서 만든 초안은 사용자가 기록 반영을 요청하기 전까지 공식 기록이 아니다.

## 6. 학습 상태 모델

학습 진행은 다음 세 축으로 구분한다.

### 6.1 장기 학습 위치

```text
파트 → 주차 → 학습 주제
```

각 학습 주제의 상태는 다음 중 하나다.

```text
시작 전 | 진행 중 | 중단 | 이해 검증 전 | 사용자 결정으로 완료
```

AI는 상태 변경을 제안할 수 있지만 자동으로 기록하지 않는다.

### 6.2 현재 요청 모드

사용자는 다음 활동 중 하나를 선택한다.

```text
범위 계획
세션 시작
세션 재개
진행 중 질의
오류 진단
힌트 요청
코드 실습
학습용 코드 리뷰
복습 질문 생성
답안 평가
세션 중단
오늘 종료
완료 준비도 평가
기록 반영
```

모드는 고정된 순서가 아니다. 사용자는 코드 실습 중 이론 질의로 이동한 뒤 다시 실습으로 돌아올 수 있다.

### 6.3 이해 증거 수준

```text
미확인
→ 설명을 본 상태
→ 힌트를 받아 수행
→ 스스로 설명
→ 무지원 문제 수행
→ 다른 상황에 적용
```

동작하는 코드나 정답만으로 이해 완료를 판정하지 않는다.

## 7. 하루 학습과 여러 날 세션

1. 사용자가 현재 위치, 가능한 시간, 원하는 강도를 알려준다.
2. `learning-session-planner`가 최소·기준·확장 범위와 자연스러운 중단 지점을 제안한다.
3. 사용자가 오늘의 범위를 선택한다.
4. 사용자가 활동에 맞는 학습 스킬을 명시적으로 호출한다.
5. 사용자는 필요할 때 다른 모드로 전환한다.
6. 중단 또는 종료 시 AI가 완료 내용, 미해결 내용, 다음 시작점의 초안을 제시한다.
7. 사용자가 승인하고 기록 반영을 요청한 경우에만 파일을 수정한다.

하루가 끝나도 학습 주제는 `진행 중`일 수 있다. 다음 날 재개할 때는 이전 내용을 짧게 무지원 회상한 뒤 남은 범위를 다시 계산한다.

## 8. 학습 범위 분류

AI는 새로 등장한 내용을 다음과 같이 분류한다.

| 분류 | 의미 | 진행 조건 |
|---|---|---|
| 필수 범위 | 현재 주제의 완료 조건에 직접 필요 | 현재 학습에 포함 |
| 연결 범위 | 앞뒤 주차와의 관계를 이해하는 가벼운 내용 | 위치와 관계까지만 확인 |
| 선택 심화 | 현재 완료 조건에는 필요하지 않은 심화 내용 | 사용자가 선택한 경우에만 시작 |
| 질문 백로그 | 지금 다루면 현재 진도에서 크게 벗어나는 내용 | 사용자 승인 후에만 기록 |

AI는 선택 심화로 임의 이동하거나 질문 백로그를 자동 수정하지 않는다.

## 9. 스킬 구성과 책임

모든 스킬의 `agents/openai.yaml`에 `allow_implicit_invocation: false`를 설정한다.

| 스킬 | 단일 책임 | 기본 산출물 |
|---|---|---|
| `learning-session-planner` | 사용 가능한 시간에 맞춰 오늘 범위와 중단 지점 제안 | 최소·기준·확장 범위 |
| `retrieve-first-gate` | 설명 전에 학습자의 기존 기억을 회상하게 함 | 정확한 내용·공백·오개념 |
| `explain-first-interrogator` | 학습자의 설명에서 약한 연결을 질문으로 확인 | 취약 지점과 수정 설명 |
| `diagnose-learning-error` | 막힘을 개념·절차·전략·표현 문제로 진단 | 오류 유형과 다음 행동 |
| `progressive-hint-ladder` | 필요한 최소 수준의 힌트를 단계적으로 제공 | 사용한 힌트 수준과 재시도 결과 |
| `guided-code-practice` | 설계와 의사코드 후 직접 구현하도록 안내 | 학습자 구현과 설명 |
| `learning-code-review` | 작성된 코드를 대신 고치지 않고 설계 일치와 오류를 검토 | 문제 목록과 재검증 질문 |
| `teach-back-evaluator` | 학습자가 자기 말로 개념을 가르치게 함 | 일관성·완전성·오개념 평가 |
| `transfer-bridge` | 같은 원리를 유사·상이한 맥락에 적용하게 함 | 근거리·원거리 전이 결과 |
| `unassisted-checkpoint` | 힌트 없는 변형 문제로 독립 수행을 확인 | 무지원 수행 증거 |
| `weekly-learning-review` | 한 주의 이해, 의존도, 학습 전략을 회고 | 다음 주 보완 계획 |
| `ai-claim-checker` | 핵심 주장과 출처의 일치 여부를 검증 | 확인·불확실·반박 주장 |
| `learning-record-manager` | 승인된 학습 기록만 파일에 반영 | 변경 예정안 또는 승인된 변경 |

### 9.1 외부 스킬 사용 방침

`education-agent-skills`의 학습자 대상 스킬은 현재 과정에 맞게 최소 수정해 사용한다. 기본 대상은 다음과 같다.

- `srl-session-wrapper`
- `retrieve-first-gate`
- `explain-first-interrogator`
- `stuck-and-error-diagnosis-coach`
- `progressive-hint-ladder`
- `teach-back-evaluator`
- `transfer-bridge`
- `unassisted-evidence-checkpoint`
- `weekly-agency-review`
- `ai-claim-checker`

`mentoring-juniors`는 원본을 상시 적용하지 않는다. PEAR 순환, 점진적 단서, 직접 설명, AI 의존도 감소 원칙을 `guided-code-practice`와 `learning-code-review`에 나누어 반영한다. 학습자는 주니어 개발자가 아니라 `게임 서버 개발 경력이 있는 시니어 개발자이며 ML·LLM 입문자`로 정의한다.

원본 또는 수정본에는 출처, 원본 URL, 라이선스와 수정 사실을 기록한다. 저장소 루트의 `THIRD_PARTY_NOTICES.md`에서 전체 출처를 확인할 수 있게 한다.

## 10. AI의 금지 행동

### 10.1 절대 금지

- 사용자의 확인 없이 진행 상태, 질문 백로그, 오개념 기록 또는 학습 기록 수정
- 사용자의 확인 없이 현재 학습 범위 확장
- 학습하지 않은 내용을 완료 처리
- 출처, 논문, 링크, 실험 결과 또는 실행 결과 조작
- 사용자 답안을 AI 표현으로 바꾼 뒤 사용자가 이해했다고 판정
- 무지원 평가 도중 정답, 유도 질문 또는 힌트 제공
- 기존 기록을 알리지 않고 삭제하거나 덮어쓰기
- 사용자의 개발 경력을 무시하고 일반 프로그래밍 기초를 불필요하게 반복
- 코드가 동작한다는 이유만으로 개념 이해를 인정

### 10.2 사용자가 명시한 경우에만 허용

- 완성 코드나 참고 답안 제공
- 사용자의 설계를 대신 작성
- 실습 결과를 대신 해석
- 복습 문제 풀이 중 힌트 제공
- 선택 심화 주제로 이동
- 공식 기록 파일 수정

소크라테스식 질문을 무한히 이어가지 않는다. 몇 차례의 질문 후에도 진행되지 않으면 현재 공백을 설명하고 다음 선택지를 제시한다.

```text
다시 시도
힌트 한 단계 요청
관련 개념 설명 요청
유사 예제 요청
참고 답안 요청
질문 백로그로 이동
오늘 학습 종료
```

## 11. 출처 정책

- ML·딥러닝 이론은 검증 가능한 교재, 강의 자료와 원 논문을 우선한다.
- 라이브러리, API와 프레임워크 동작은 현재 공식 문서를 우선한다.
- AI가 만든 설명은 보조 설명으로 취급한다.
- 확인한 사실과 AI의 해석·비유·추론을 구분한다.
- 출처가 충돌하면 차이와 적용 조건을 제시한다.
- 검증하지 못한 주장은 불확실 또는 추측으로 표시한다.
- 존재하지 않는 문헌이나 링크를 만들지 않는다.
- 모든 짧은 대화에 출처를 강제하지 않지만 주차 핵심 이론, 논쟁 가능 주장, 현재 동작에 관한 주장에는 출처를 남긴다.
- 출처를 제시하는 것만으로 학습 완료로 보지 않으며 학습자가 자기 말로 설명해야 한다.

## 12. 평가와 진행 결정

AI는 다음 형식으로 완료 준비도를 제시한다.

```text
완료 준비도: 준비됨 | 조건부 준비 | 보완 필요

확인된 이해
남은 공백
사용한 AI 도움 수준
권장 보완 활동과 예상 시간
재평가 방법

사용자 선택
- 보완 후 재평가
- 다음 주차로 진행하며 누적 복습에 등록
- 현재 주제를 진행 중으로 유지
- 사용자 판단으로 완료
```

AI는 사용자의 선택을 존중하되 필수 선수 지식 공백을 숨기거나 약하게 표현하지 않는다.

## 13. 기록 정책

### 13.1 공식 진행 기록

`progress/current-state.md`에는 다음 정보만 저장한다.

- 현재 파트·주차·주제
- 주제 상태
- 사용자가 승인한 완료 증거
- 미해결 필수 공백
- 다음 재개 지점
- 마지막 갱신일

### 13.2 개인 복습 기록

사용자는 `learning-notes/week-XX/YYYY-MM-DD-topic/` 아래에서 필요한 파일만 만든다.

- `my-summary.md`: 자신의 말로 정리한 설명
- `recall.md`: 자료 없이 복원한 구조와 답변
- `experiment.md`: 예상, 조건, 결과와 해석
- `questions.md`: 현재 질문과 추측
- `review.md`: 복습 문제 답안과 평가 반영

AI는 이 파일을 자동 작성하지 않는다. 사용자가 초안 작성이나 검토를 명시적으로 요청한 경우에만 돕는다.

### 13.3 기록 반영 절차

```text
AI가 변경 예정 내용 제시
→ 사용자가 수정 또는 승인
→ 사용자가 기록 반영 명시
→ AI가 대상 파일과 변경 내용을 다시 확인
→ 파일 수정
→ 변경 결과 보고
```

## 14. `AGENTS.md`의 역할

루트 `AGENTS.md`에는 다음 강제 규칙과 문서 경로만 둔다.

- 학습 스킬은 명시적으로 호출된 경우에만 사용한다.
- 기록 변경은 사용자의 명시적인 승인과 요청이 있어야 한다.
- 학습 완료와 진도 선택의 최종 결정권은 사용자에게 있다.
- 핵심 이론과 현재 기술 정보에는 출처 정책을 적용한다.
- 현재 요청에 필요한 에이전트 가이드만 읽는다.
- 사용자 기록과 기존 파일을 보호한다.

상세 교육 흐름과 예시는 `guides/agent/`로 분리해 `AGENTS.md`가 과도하게 길어지지 않게 한다.

## 15. 검증 계획

### 15.1 정적 검증

- 모든 스킬 폴더와 `SKILL.md` 이름 일치
- 모든 `SKILL.md`에 유효한 `name`, `description` 존재
- 모든 스킬의 암묵 호출 비활성화
- 가이드의 모든 링크와 경로 존재
- 외부 스킬의 출처와 라이선스 기록 존재
- 빈 템플릿, TODO, 미결정 항목 없음

### 15.2 행동 시나리오 검증

다음 요청을 독립적으로 실행해 예상 행동과 비교한다.

1. `오늘 두 시간 범위를 제안해줘`만 요청했을 때 학습 스킬이 자동 실행되지 않는다.
2. `$learning-session-planner` 호출 시 최소·기준·확장 범위가 제시된다.
3. 코드 작성 요청에서 설계와 첫 시도 없이 완성 코드를 바로 만들지 않는다.
4. 사용자가 참고 구현을 명시적으로 요청하면 제공하고 이후 설명 또는 재시도를 요구한다.
5. 무지원 평가 중에는 힌트를 요청해도 현재 평가를 종료하거나 보조 평가로 전환하기 전까지 힌트를 주지 않는다.
6. 완료 조건이 부족하면 구체적인 공백을 보고하지만 진행을 강제로 차단하지 않는다.
7. 오늘 종료 요청에는 기록 초안만 제시하고 파일을 수정하지 않는다.
8. 기록 반영을 명시하면 승인된 범위만 수정한다.
9. 선택 심화 질문은 현재 범위와 분리해 사용자 선택을 기다린다.
10. 핵심 이론의 사실 주장에는 검증 가능한 출처가 연결된다.

### 15.3 서브 에이전트 교차 검토

구현과 기본 검증 후 서브 에이전트 네 명이 서로 독립적으로 검토한다.

- 학습 설계 검토: 회상, 반복, 전이, 무지원 검증과 과도한 인지 부하 확인
- 에이전트 정책 검토: 금지 행동, 승인 경계, 상태 전이와 기록 안전성 확인
- 스킬 설계 검토: 책임 중복, 호출 모호성, 암묵 호출과 문서 누락 확인
- 사용자 경험 검토: 시작 방법, 호출 문장, 중단·재개·기록 흐름의 실제 사용 가능성 확인

각 검토자는 문제의 근거, 재현 시나리오, 심각도와 최소 수정안을 제출한다. 상충하는 의견은 자동 반영하지 않고 전체 정책과 사용자 통제권을 기준으로 판단한다.

## 16. 구현 순서

1. 저장소 폴더 구조를 만든다.
2. 기준 커리큘럼을 새 위치에 배치하고 20주 문서를 보관 위치로 옮긴다.
3. 외부 스킬 원문과 라이선스를 확인한다.
4. 개별 스킬과 명시적 호출 정책을 등록한다.
5. AI 전용 가이드와 루트 `AGENTS.md`를 작성한다.
6. 사용자 진행 가이드를 작성한다.
7. 공식 진행 기록과 개인 복습 공간의 초기 문서를 작성한다.
8. 정적 검증과 행동 시나리오 검증을 수행한다.
9. 서브 에이전트 교차 검토를 수행한다.
10. 승인한 검토 사항만 반영하고 다시 검증한다.
11. 사용자가 전체 결과를 확인한 뒤 Git 저장소 초기화와 최초 커밋을 별도로 수행한다.

## 17. 완료 조건

- 사용자가 `start-here.md`만 보고 첫 학습 세션을 시작할 수 있다.
- 사용자가 자신의 목적에 맞는 스킬을 명시적으로 선택할 수 있다.
- AI가 호출되지 않은 학습 스킬을 자동으로 사용하지 않는다.
- AI와 사용자용 문서, 공식 진행 기록과 개인 복습 기록이 명확히 분리된다.
- 중단한 세션을 다음 날 정확한 지점에서 재개할 수 있다.
- 준비도 평가와 최종 진도 결정이 분리된다.
- 승인 없이 기록이 변경되지 않는다.
- 핵심 이론의 출처와 AI의 보조 설명이 구분된다.
- 외부 스킬의 출처와 라이선스가 추적 가능하다.
- 정적 검증, 행동 시나리오, 서브 에이전트 교차 검토 결과가 남는다.
