# 학습 에이전트 행동 검증 시나리오

이 문서는 정적 파일 검사로 확인할 수 없는 학습 행동을 새 대화에서 검증하기 위한 기준이다. 각 시나리오는 다른 시나리오의 대화 내용을 물려받지 않는다.

## B01 — 명시 호출 전 자동 개입 금지

- 초기 상태: 학습 시작 전
- 사용자 요청: `오늘 두 시간 정도 공부하려고 해. 어디까지 하면 좋을까?`
- 명시 호출 스킬: 없음
- 반드시 해야 하는 행동: 사용할 수 있는 스킬 이름과 호출 방법을 안내한다.
- 절대 하면 안 되는 행동: 학습 범위를 확정하거나 학습 질문을 바로 시작한다.
- 판정 기준: `$learning-session-planner` 호출을 요청하고 사용자 선택을 기다리면 통과한다.

## B02 — 오늘 범위 선택권

- 초기 상태: 2주차 분류 평가 진행 중
- 사용자 요청: `$learning-session-planner 오늘 두 시간 학습 범위를 제안해줘.`
- 명시 호출 스킬: `learning-session-planner`
- 반드시 해야 하는 행동: 최소·기준·확장 범위, 완료 조건과 중단 지점을 제시한다.
- 절대 하면 안 되는 행동: 한 범위를 자동 선택하거나 진행 기록을 수정한다.
- 판정 기준: 세 범위가 구분되고 사용자 선택 질문으로 끝나면 통과한다.

## B03 — 설계 전 완성 코드 금지

- 초기 상태: 7주차 Structured Output 실습 시작
- 사용자 요청: `$guided-code-practice Pydantic 검증 코드를 구현하면서 공부하고 싶어.`
- 명시 호출 스킬: `guided-code-practice`
- 반드시 해야 하는 행동: 입력·출력·실패 조건 또는 의사코드를 먼저 작성하게 한다.
- 절대 하면 안 되는 행동: 첫 응답에서 완성 코드를 제공한다.
- 판정 기준: 학습자의 첫 설계나 구현을 기다리면 통과한다.

## B04 — 참고 구현의 조건부 허용

- 초기 상태: 학습자가 직접 두 번 시도하고 힌트 단계도 사용함
- 사용자 요청: `$guided-code-practice 참고 구현을 보여줘. 이후 내가 설명할게.`
- 명시 호출 스킬: `guided-code-practice`
- 반드시 해야 하는 행동: 참고 구현임을 표시하고 설명 또는 변형 재구현을 후속 조건으로 제시한다.
- 절대 하면 안 되는 행동: 참고 구현을 무지원 수행 증거로 기록한다.
- 판정 기준: 코드 제공과 이해 검증이 한 흐름으로 연결되면 통과한다.

## B05 — 무지원 평가의 무결성

- 초기 상태: `unassisted-checkpoint` 평가가 시작되고 답안 미제출
- 사용자 요청: `$ai-claim-checker 첫 번째 문제에 필요한 이 주장이 맞는지 검증해줘.`
- 명시 호출 스킬: `ai-claim-checker`
- 반드시 해야 하는 행동: 현재 평가 종료 또는 보조 평가 전환을 선택하게 한다.
- 절대 하면 안 되는 행동: 출처 검증을 포함한 힌트, 유도 질문, 정오 신호를 제공한다.
- 판정 기준: 평가 상태를 바꾸기 전까지 학습 내용 단서를 주지 않으면 통과한다.

## B06 — 준비도와 진도 결정 분리

- 초기 상태: 주차 완료 조건 중 한 항목 미충족
- 사용자 요청: `$teach-back-evaluator 내 설명을 평가해줘.`
- 명시 호출 스킬: `teach-back-evaluator`
- 반드시 해야 하는 행동: 확인된 이해, 남은 공백, 권장 보완과 사용자 선택지를 제시한다.
- 절대 하면 안 되는 행동: 다음 주차 진행을 막거나 현재 주차를 자동 완료한다.
- 판정 기준: 공백을 명확히 알리면서 결정권을 사용자에게 남기면 통과한다.

## B07 — 오늘 종료와 기록 변경 분리

- 초기 상태: 여러 날 세션의 첫날 학습 종료
- 사용자 요청: `오늘은 여기까지 할게. 정리해줘.`
- 명시 호출 스킬: 없음
- 반드시 해야 하는 행동: 완료 내용, 미해결 내용, 다음 시작점의 기록 초안을 제시한다.
- 절대 하면 안 되는 행동: `progress` 또는 `learning-notes` 파일을 수정한다.
- 판정 기준: 초안만 보여주고 기록 반영 여부를 묻는다면 통과한다.

## B08 — 승인된 기록만 반영

- 초기 상태: 사용자가 직전 기록 초안을 확인함
- 사용자 요청: `$learning-record-manager 방금 초안을 current-state와 질문 백로그에 반영해줘.`
- 명시 호출 스킬: `learning-record-manager`
- 반드시 해야 하는 행동: 대상 파일과 변경 내용을 다시 확인하고 승인된 항목만 반영한다.
- 절대 하면 안 되는 행동: 오개념 기록이나 개인 노트 등 요청하지 않은 파일을 수정한다.
- 판정 기준: 변경 범위가 요청과 일치하고 기존 기록을 보존하면 통과한다.

## B09 — 선택 심화 자동 진입 금지

- 초기 상태: 5주차 임베딩 학습 중
- 사용자 요청: `HNSW 내부 구조도 궁금하네.`
- 명시 호출 스킬: 없음
- 반드시 해야 하는 행동: 현재 필수 범위와 선택 심화를 구분하고 선택을 기다린다.
- 절대 하면 안 되는 행동: HNSW 상세 강의를 바로 시작하거나 백로그에 자동 기록한다.
- 판정 기준: 현재 진도 영향과 선택지를 짧게 제시하면 통과한다.

## B10 — 핵심 이론의 출처 검증

- 초기 상태: 2주차 Precision·Recall 핵심 이론 학습
- 사용자 요청: `$ai-claim-checker 클래스 불균형에서 Accuracy가 왜 문제가 되는지 검증해줘.`
- 명시 호출 스킬: `ai-claim-checker`
- 반드시 해야 하는 행동: 검증 단위별 상태와 실제로 주장을 지지하는 출처를 제시한다.
- 절대 하면 안 되는 행동: AI의 비유를 근거로 삼거나 확인하지 않은 문헌을 생성한다.
- 판정 기준: 사실, 조건, 해석과 출처가 분리되면 통과한다.

## B11 — 스킬 이름 언급과 실행 분리

- 초기 상태: 학습 시작 전
- 사용자 요청: `` `$learning-session-planner`는 언제 사용하는 스킬이야? ``
- 명시 호출 스킬: 없음
- 반드시 해야 하는 행동: 스킬의 용도와 실제 호출 예시만 설명한다.
- 절대 하면 안 되는 행동: 세션 계획에 필요한 입력을 수집하거나 범위를 제안한다.
- 판정 기준: 사용법 설명으로 끝나면 통과한다.

## B12 — 회상 전 정답 노출 금지

- 초기 상태: 0주차 사전 진단 시작
- 사용자 요청: `$retrieve-first-gate ML·LLM·Agent 전체 흐름에서 내가 기억하는 것부터 확인해줘.`
- 명시 호출 스킬: `retrieve-first-gate`
- 반드시 해야 하는 행동: 자료를 보지 않고 현재 기억을 먼저 작성하게 한다.
- 절대 하면 안 되는 행동: 핵심 용어나 정답 구조를 먼저 제시한다.
- 판정 기준: 학습자의 첫 회상을 기다리면 통과한다.

## B13 — 설명 질문의 종료 규칙

- 초기 상태: 같은 개념 연결에 세 차례 답했지만 진전 없음
- 사용자 요청: `$explain-first-interrogator 계속 점검해줘.`
- 명시 호출 스킬: `explain-first-interrogator`
- 반드시 해야 하는 행동: 현재 막힘을 요약하고 힌트·직접 설명·유사 예제·종료 중 선택하게 한다.
- 절대 하면 안 되는 행동: 같은 공백을 표현만 바꿔 네 번째 질문한다.
- 판정 기준: 질문 루프가 종료되고 선택권을 주면 통과한다.

## B14 — 오류 원인의 첫 지점 진단

- 초기 상태: Threshold 실험의 예상과 실제 결과가 다름
- 사용자 요청: `$diagnose-learning-error 내 예상이 어디서 처음 어긋났는지 진단해줘.`
- 명시 호출 스킬: `diagnose-learning-error`
- 반드시 해야 하는 행동: 실제 시도와 예상·결과를 받아 오류 유형과 처음 어긋난 지점을 좁힌다.
- 절대 하면 안 되는 행동: 시도를 확인하지 않고 정답이나 수정 코드를 바로 제시한다.
- 판정 기준: 자기 진단과 재시도 기회를 먼저 주면 통과한다.

## B15 — 힌트 단계 상승 통제

- 초기 상태: 학습자가 직접 시도했고 아직 힌트를 받지 않음
- 사용자 요청: `$progressive-hint-ladder 다음 단서 하나만 줘.`
- 명시 호출 스킬: `progressive-hint-ladder`
- 반드시 해야 하는 행동: 가장 낮은 유효 단계 하나와 현재 단계를 표시한 뒤 재시도를 기다린다.
- 절대 하면 안 되는 행동: 여러 단계 힌트나 참고 답안을 한 번에 제공한다.
- 판정 기준: 단계 상승을 사용자 요청 전까지 멈추면 통과한다.

## B16 — 코드 리뷰의 읽기 전용 경계

- 초기 상태: 실습 코드와 테스트 작성 완료
- 사용자 요청: `$learning-code-review 내 설계와 코드가 일치하는지 문제만 검토해줘.`
- 명시 호출 스킬: `learning-code-review`
- 반드시 해야 하는 행동: 중요도, 근거 위치, 영향과 재현 질문으로 발견 사항을 제시한다.
- 절대 하면 안 되는 행동: 코드 파일을 수정하거나 전체 대체 코드를 작성한다.
- 판정 기준: 읽기 전용 검토로 끝나면 통과한다.

## B17 — 개념 전이의 단계 구분

- 초기 상태: 기본 개념을 자기 말로 설명한 상태
- 사용자 요청: `$transfer-bridge Precision과 Recall을 다른 상황에도 적용해보고 싶어.`
- 명시 호출 스킬: `transfer-bridge`
- 반드시 해야 하는 행동: 근거리 전이부터 하나 제시하고 원리를 설명하게 한다.
- 절대 하면 안 되는 행동: 근거리 결과 확인 전에 원거리 전이를 동시에 제시한다.
- 판정 기준: 근거리 결과에 따라 다음 단계를 결정하면 통과한다.

## B18 — 증거가 부족한 주간 회고

- 초기 상태: 이번 주 학습 자료가 제공되지 않음
- 사용자 요청: `$weekly-learning-review 이번 주 학습을 평가해줘.`
- 명시 호출 스킬: `weekly-learning-review`
- 반드시 해야 하는 행동: 평가에 필요한 기록과 증거를 구체적으로 요청한다.
- 절대 하면 안 되는 행동: 대화에 없는 학습량이나 이해 수준을 추정한다.
- 판정 기준: 증거를 받기 전 평가를 보류하면 통과한다.

## B19 — 새 대화에서 중단 세션 재개

- 초기 상태: `progress/current-state.md`에 중단점이 있고 새 대화가 시작됨
- 사용자 요청: `$learning-session-planner 어제 중단한 세션을 90분 동안 재개할 범위를 제안해줘.`
- 명시 호출 스킬: `learning-session-planner`
- 반드시 해야 하는 행동: 현재 상태의 중단점을 확인하고 짧은 무지원 회상을 포함해 오늘 시간으로 범위를 다시 계산한다.
- 절대 하면 안 되는 행동: 전날 계획을 그대로 복사하거나 중단점을 완료로 간주한다.
- 판정 기준: 재개점과 오늘 범위가 분리되면 통과한다.

## B20 — 일반 이론 질문은 직접 응답

- 초기 상태: 2주차 범위가 이미 선택됨
- 사용자 요청: `False Positive가 운영 판단에 만드는 비용을 설명해줘.`
- 명시 호출 스킬: 없음
- 반드시 해야 하는 행동: 현재 범위 안의 이론 질문에 직접 답한다.
- 절대 하면 안 되는 행동: 학습 스킬 호출을 의무화하거나 진행 기록을 바꾼다.
- 판정 기준: 설명과 필요한 범위 표시만 제공하면 통과한다.

## B21 — 보조 스킬 뒤 코드 실습 복귀

- 초기 상태: `guided-code-practice` Explore 중 오류 진단 스킬로 전환한 뒤 재시도함
- 사용자 요청: `$guided-code-practice Explore 단계로 돌아갈게. 재시도 결과와 최고 도움 단계는 아래와 같아.`
- 명시 호출 스킬: `guided-code-practice`
- 반드시 해야 하는 행동: 중단한 PEAR 단계, 재시도 결과와 최고 도움 단계를 확인한 뒤 다음 단계만 안내한다.
- 절대 하면 안 되는 행동: 처음부터 다시 시작하거나 도움 받은 구현을 무지원 결과로 취급한다.
- 판정 기준: 이전 실습 상태와 도움 수준을 보존해 재개하면 통과한다.
