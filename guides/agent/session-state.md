# 학습 세션 상태

학습 위치, 현재 요청과 이해 증거를 하나의 상태값으로 합치지 않는다. 세 축을 따로 확인해야 여러 날 세션과 활동 전환을 정확히 처리할 수 있다.

## 1. 장기 학습 위치

```text
파트 → 주차 → 학습 주제
```

학습 주제 상태:

```text
시작 전 | 진행 중 | 중단 | 이해 검증 전 | 사용자 결정으로 완료
```

- `중단`은 실패나 미완료 판정이 아니라 다음 재개점이 있는 상태다.
- `이해 검증 전`은 이론이나 실습을 진행했지만 독립 설명 또는 무지원 증거가 아직 없는 상태다.
- `사용자 결정으로 완료`는 AI 평가가 아니라 사용자 선택으로만 설정한다.
- 상태 변경은 [평가와 기록 정책](evaluation-and-record-policy.md)에 따라 승인 후 기록한다.

## 2. 현재 요청 모드

```text
범위 계획
세션 시작
세션 재개
진행 중 질의
오류 진단
힌트 요청
코드 실습
학습용 코드 리뷰
복습 질문 생성
답안 평가
세션 중단
오늘 종료
완료 준비도 평가
기록 반영
```

요청 모드는 고정 순서가 아니다. 코드 실습 중 이론 질문으로 이동한 뒤 같은 실습으로 돌아갈 수 있다. 모드가 바뀌어도 장기 학습 위치는 자동으로 바뀌지 않는다.

명시 호출된 스킬은 종료 조건, 사용자 중단 또는 다른 명시 호출까지 현재 활동으로 유지된다. 다른 스킬로 전환하면 기존 활동은 중단되며, 복귀할 때 이전 스킬을 다시 호출하고 중단 단계와 받은 도움 수준을 전달한다. 무지원 평가가 활성 상태라면 [운영 정책](operating-policy.md)의 전역 가드를 먼저 적용한다.

## 3. 이해 증거 수준

```text
미확인
→ 설명을 본 상태
→ 힌트를 받아 수행
→ 스스로 설명
→ 무지원 문제 수행
→ 다른 상황에 적용
```

- 높은 단계가 낮은 단계의 모든 지식을 영구히 보장하지 않는다.
- 도움을 받은 산출물에는 사용한 도움 수준을 남긴다.
- 정답, 코드 실행 성공과 문서 분량은 독립 이해 증거가 아니다.
- 완료 준비도는 현재 주제의 완료 조건과 실제 증거를 함께 비교한다.

## 하루 세션 시작

사용자가 현재 위치, 가능한 시간과 원하는 강도를 제시하면 다음 순서로 처리한다.

1. 활성 세션과 이전 중단점이 있는지 확인한다.
2. 새 세션인지 재개인지 사용자에게 보여준다.
3. `$learning-session-planner`가 호출됐을 때만 최소·기준·확장 범위를 제안한다.
4. 사용자가 범위를 선택할 때까지 학습을 시작하지 않는다.
5. 선택된 범위와 완료 조건을 대화 안에서 확인한다. 기록은 아직 바꾸지 않는다.

## 중단과 재개

중단 시 다음 초안을 제시한다.

```text
오늘 확인한 내용
아직 확인하지 못한 내용
사용한 AI 도움 수준
자연스러운 다음 시작점
재개할 때 먼저 회상할 질문
```

다음 날 재개할 때는 이전 내용을 짧게 자료 없이 회상하고 남은 시간을 기준으로 범위를 다시 계산한다. 전날 계획을 기계적으로 유지하지 않는다.

## 오늘 종료와 주제 완료

- `오늘 종료`는 그날의 학습만 닫는다. 주제 상태는 진행 중 또는 중단일 수 있다.
- `주제 완료`는 완료 조건과 이해 증거를 검토한 뒤 사용자가 결정한다.
- 오늘 종료 초안이나 완료 준비도 평가만으로 파일을 수정하지 않는다.
