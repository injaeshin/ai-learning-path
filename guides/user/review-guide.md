# 복습 가이드

문서를 다시 읽는 것보다 자료 없이 구조를 꺼내고 설명한 뒤, 다른 문제에 적용하는 순서를 사용한다.

## 1. 구조 복원

빈 화면에서 현재 주제의 데이터 흐름이나 관계를 다시 그린다.

```text
User
 ↓
???
 ↓
???
 ↓
Tool
 ↓
???
 ↓
LLM
```

완성도를 먼저 보지 말고 기억나는 만큼 적는다. 이후 `$retrieve-first-gate`로 정확한 내용, 누락과 오개념을 구분한다.

## 2. 연속 질문

자신의 설명을 적고 `$explain-first-interrogator`를 호출한다. 다음 종류의 질문에 답하지 못하는 부분만 다시 본다.

- 각 구성 요소의 입력과 출력은 무엇인가?
- 실제 상태 변화는 어디에서 일어나는가?
- 왜 다음 단계가 필요한가?
- 어떤 조건에서 실패하는가?
- 앞뒤 주차의 어떤 개념과 연결되는가?

## 3. 티치백

전체 흐름을 다른 개발자에게 가르치듯 설명한다.

```text
$teach-back-evaluator

내가 지금부터 Agent Loop를 처음 배우는 서버 개발자에게 설명할게.
설명을 끝낼 때까지 기다린 뒤 메커니즘과 오개념 위험을 평가해줘.
```

AI의 수정 설명을 복사하지 말고 자신의 설명을 다시 쓴다.

## 4. 전이 확인

기본 설명이 가능하면 `$transfer-bridge`로 다음을 확인한다.

- 근거리: 숫자, 데이터 또는 표면 상황만 바뀐 문제
- 원거리: 다른 주차나 게임 서버 맥락에서 같은 원리를 찾는 문제

정답을 맞혀도 원리를 설명하지 못했다면 절차적 성공으로 보고 보완한다.

## 5. 무지원 평가

주제 또는 주차 완료 전 `$unassisted-checkpoint`를 사용한다.

- 평가 범위와 자료 사용 규칙을 먼저 정한다.
- 답안 제출 전에는 힌트와 정오 반응을 받지 않는다.
- 힌트가 필요해지면 평가 종료 또는 보조 평가 전환을 먼저 선택한다.
- 함께 풀었던 문제와 다른 변형 문제로 확인한다.

## 금요일 누적 복습 예시

1. 전체 시스템 지도를 빈 화면에서 다시 그린다.
2. 이번 주 개념 세 개를 자신의 말로 설명한다.
3. 이전 주 개념 하나와의 연결을 설명한다.
4. 답하지 못한 부분만 자료에서 다시 찾는다.
5. `$weekly-learning-review`로 다음 주에 다시 꺼낼 항목을 최대 세 개 정한다.
6. 취약 개념이 이후 파트에서 다시 등장한다면 그 연결 주차를 다음 재검증 시점으로 남긴다.

복습 결과는 바로 공식 기록이 아니다. 기록하려면 내용을 검토한 뒤 `$learning-record-manager`를 별도로 호출한다.
