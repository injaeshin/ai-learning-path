# 스킬 호출 가이드

학습 스킬은 `$skill-name`과 지금 실행할 의도를 직접 요청한 경우에만 작동한다. 이름을 인용하거나 코드 블록·과거 대화 안에 적거나 사용법을 묻는 것은 호출이 아니다. 한 번에 현재 목적을 담당하는 스킬 하나를 선택한다.

호출된 스킬은 활동을 끝내거나 사용자가 중단하거나 다른 스킬을 명시적으로 호출할 때까지 같은 활동의 후속 대화에 유지된다. 다른 스킬로 전환했다가 돌아올 때는 이전 스킬을 다시 호출하고 중단 지점과 받은 도움 수준을 알려준다. 무지원 평가 중에는 다른 스킬을 호출해도 평가를 끝내거나 보조 평가로 전환하기 전까지 학습 내용의 도움을 받을 수 없다.

## `$learning-session-planner`

- 언제: 오늘 가능한 시간에 맞춰 범위와 중단점을 정할 때
- 필수 입력: 현재 위치, 가능한 시간, 새 세션 또는 재개 여부
- 호출 예시: `$learning-session-planner 5주차 임베딩을 오늘 2시간 진행할 범위로 나눠줘.`
- 기대 출력: 최소·기준·확장 범위, 완료 조건, 중단점
- 사용하지 말 때: 범위를 이미 선택하고 구체적인 이론 질문만 할 때

## `$retrieve-first-gate`

- 언제: 새로운 설명을 보기 전 또는 복습을 시작할 때
- 필수 입력: 회상할 개념과 범위
- 호출 예시: `$retrieve-first-gate LLM과 Agent의 차이를 보기 전에 내가 기억하는 것부터 확인해줘.`
- 기대 출력: 회상 성공, 누락, 오개념 후보
- 사용하지 말 때: 처음 접하는 주제의 최소 지도도 없는 경우에는 처음이라고 함께 알린다.

## `$explain-first-interrogator`

- 언제: 자신이 작성한 이론 설명의 약한 연결을 찾을 때
- 필수 입력: 개념과 자신의 설명
- 호출 예시: `$explain-first-interrogator 아래 Attention 설명에서 약한 부분을 질문으로 확인해줘.`
- 기대 출력: 최대 세 질문, 수정할 연결, 재설명 요청
- 사용하지 말 때: 완성된 종합 평가를 원하면 `$teach-back-evaluator`를 사용한다.

## `$diagnose-learning-error`

- 언제: 계산, 이론, 실험 또는 코드가 어디서 잘못됐는지 모를 때
- 필수 입력: 문제, 실제 시도, 예상과 실제 결과
- 호출 예시: `$diagnose-learning-error 이 threshold 실험에서 내 예상이 왜 틀렸는지 진단해줘.`
- 기대 출력: 오류 유형, 처음 어긋난 지점, 자기 수정 질문
- 사용하지 말 때: 원인은 알고 다음 단서만 필요하면 `$progressive-hint-ladder`를 사용한다.

## `$progressive-hint-ladder`

- 언제: 직접 시도한 뒤 다음 단서 하나가 필요할 때
- 필수 입력: 문제, 시도, 막힌 지점, 이미 받은 도움
- 호출 예시: `$progressive-hint-ladder 2단계 개념 질문까지만 줘.`
- 기대 출력: 현재 힌트 단계와 재시도 요청
- 사용하지 말 때: 진행 중인 무지원 평가에서는 먼저 평가 상태를 바꾼다.

## `$guided-code-practice`

- 언제: 설계부터 직접 코드로 구현하며 배우고 싶을 때
- 필수 입력: 주차 목표, 구현 범위, 완료 조건
- 호출 예시: `$guided-code-practice Tool Schema 검증기를 설계부터 직접 구현하게 안내해줘.`
- 기대 출력: Plan·Explore·Analyze·Rewrite 흐름
- 사용하지 말 때: 작성한 코드 검토만 원하면 `$learning-code-review`를 사용한다.

## `$learning-code-review`

- 언제: 구현을 끝낸 뒤 코드 수정 없이 문제만 검토받을 때
- 필수 입력: 설계, 코드, 테스트, 기대 결과
- 호출 예시: `$learning-code-review 이 구현이 내 설계와 일치하는지 문제만 알려줘.`
- 기대 출력: 중요도 순 문제, 근거, 재현·확인 질문
- 사용하지 말 때: AI가 코드를 직접 고치길 원하는 일반 구현 작업

## `$teach-back-evaluator`

- 언제: 한 개념을 다른 개발자에게 가르치듯 설명하고 평가받을 때
- 필수 입력: 개념, 현재 주차, 자신의 설명
- 호출 예시: `$teach-back-evaluator 내가 설명하는 RAG 흐름을 평가해줘.`
- 기대 출력: 일관성·완전성·메커니즘·오개념 위험 평가
- 사용하지 말 때: 설명 전 기억만 확인하려면 `$retrieve-first-gate`를 사용한다.

## `$transfer-bridge`

- 언제: 같은 원리를 다른 상황에도 적용할 수 있는지 확인할 때
- 필수 입력: 학습한 개념과 원래 예제
- 호출 예시: `$transfer-bridge Precision과 Recall을 검색 평가와 게임 이상 탐지에 적용해 확인해줘.`
- 기대 출력: 근거리·원거리 전이 문제와 결과
- 사용하지 말 때: 기본 개념을 자기 말로 아직 설명하지 못할 때

## `$unassisted-checkpoint`

- 언제: 힌트 없이 독립 수행할 수 있는지 확인할 때
- 필수 입력: 평가 범위, 자료 사용 규칙, 답안 형식
- 호출 예시: `$unassisted-checkpoint 2주차 완료 조건을 힌트 없이 평가해줘.`
- 기대 출력: 평가 계약, 변형 문제, 제출 후 평가
- 사용하지 말 때: 학습 도중 힌트를 자유롭게 받고 싶은 경우

## `$weekly-learning-review`

- 언제: 한 주의 이해 증거와 다음 누적 복습을 정할 때
- 필수 입력: 이번 주 학습 주제와 검토할 기록
- 호출 예시: `$weekly-learning-review 이번 주 설명·실험·무지원 결과를 기준으로 회고해줘.`
- 기대 출력: 확인된 증거, 반복 공백, AI 의존도, 다음 복습
- 사용하지 말 때: 단순 시간 합계나 일정을 만드는 경우

## `$ai-claim-checker`

- 언제: AI 설명이나 노트의 핵심 사실과 출처를 확인할 때
- 필수 입력: 검증할 주장과 현재 학습 맥락
- 호출 예시: `$ai-claim-checker 이 Transformer 설명의 핵심 주장을 출처와 대조해줘.`
- 기대 출력: 확인됨·조건부·불확실·반박됨 상태와 근거
- 사용하지 말 때: 표현과 문장만 다듬고 사실 검증은 필요 없는 경우

## `$learning-record-manager`

- 언제: 검토하고 승인한 내용을 파일에 실제 반영할 때
- 필수 입력: 승인된 내용, 대상 기록 또는 파일, 명시적 반영 요청
- 호출 예시: `$learning-record-manager 방금 승인한 중단 기록만 current-state에 반영해줘.`
- 기대 출력: 변경 대상 확인, 최소 파일 수정, 보존 내용 보고
- 사용하지 말 때: 초안을 만들거나 아직 기록을 검토 중인 경우
