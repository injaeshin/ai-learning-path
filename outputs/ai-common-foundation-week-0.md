# 0주차 — AI 시스템 전체 지도

## 과정 정의

- 시간: 총 10시간
- 구성: 2시간 × 5회
- 위치: 1~16주 공통 이해 과정 시작 전
- 성격: 전체 흐름 이론과 가벼운 관찰 실습
- 목표: 상세 원리를 이해하는 것이 아니라, 앞으로 배울 개념의 위치·역할·연결 관계를 먼저 파악한다.

0주차에서는 ML 모델, LLM, Agent, RAG를 직접 깊게 구현하지 않는다. 준비된 작은 예제와 최소 코드를 실행하면서 입력, 출력, 상태 변화, 대표적인 실패를 관찰한다. 이해하지 못한 세부 내용은 해결하려고 오래 붙잡지 않고 `질문 백로그`에 기록한 뒤 해당 주차에서 다시 학습한다.

## 핵심 질문

> 사용자의 질문이 데이터, 모델, 검색, 도구, 실행 상태, 평가를 거쳐 하나의 AI 응답이 될 때 각 구성 요소는 무엇을 담당하며 어디에서 실패할 수 있는가?

## 기준 시나리오

0주차의 모든 활동은 하나의 GameOps 시나리오를 공유한다.

```text
최근 매치 실패율이 증가했는지 확인하고,
관련된 운영 문서를 근거로 가능한 원인을 설명해줘.
```

이 요청을 다음 흐름으로 관찰한다.

```text
사용자 질문
  ↓
요청 해석과 입력 검증
  ↓
게임 지표 데이터 조회
  ↓
관련 운영 문서 검색
  ↓
LLM Context 구성
  ↓
필요한 Tool 선택과 실행
  ↓
근거가 포함된 답변 생성
  ↓
품질·권한·비용·지연 확인
```

## 0주차에서 알아야 할 수준

각 개념은 다음 네 가지까지만 이해한다.

1. 전체 흐름에서 어디에 위치하는가?
2. 무엇을 입력받고 무엇을 출력하는가?
3. 대표적인 실패는 무엇인가?
4. 어느 주차에서 다시 깊게 배우는가?

수식 유도, 프레임워크 사용법, 구현 최적화, 상세 아키텍처는 0주차 평가 범위가 아니다.

## 1회차 — 전체 흐름과 구성 요소

### 시간

2시간

### 학습 목표

- AI, ML 모델, LLM, RAG, Agent를 같은 개념으로 취급하지 않는다.
- 하나의 사용자 요청이 여러 구성 요소를 거쳐 처리된다는 것을 이해한다.
- 각 구성 요소의 입력과 출력을 대략적으로 구분한다.

### 진행

| 시간 | 활동 |
|---:|---|
| 20분 | 사전 진단: 알고 있는 용어와 모르는 용어 표시 |
| 35분 | 전체 시스템 지도와 구성 요소의 역할 학습 |
| 35분 | 기준 시나리오의 요청 흐름 단계별 추적 |
| 20분 | 자료를 닫고 전체 흐름 다시 그리기 |
| 10분 | 질문 백로그 작성 |

### 핵심 개념

```text
Data
Model
LLM
Prompt / Context
Retrieval / RAG
Tool Calling
Agent Loop
State / Event
Evaluation
Safety / Operations
```

### 가벼운 실습

기준 시나리오를 다음 표로 분해한다.

| 단계 | 입력 | 처리 | 출력 | 대표 실패 |
|---|---|---|---|---|
| 데이터 조회 | 기간과 지표 이름 | 게임 지표 집계 | 실패율 | 누락·잘못된 기간 |
| 문서 검색 | 장애 관련 질의 | 관련 문서 탐색 | 근거 문서 | 관련 문서 미검색 |
| LLM | 질문과 검색 결과 | 응답 생성 | 분석 문장 | 근거 없는 주장 |
| Tool 실행 | Tool 이름과 인자 | 실제 함수 실행 | Tool Result | 잘못된 인자·권한 |
| 평가 | 실행 결과와 기준 | 품질·비용 측정 | 평가 결과 | 잘못된 평가 기준 |

표를 완벽히 채우는 것이 목적은 아니다. 어떤 실패가 어느 단계에서 발생했는지 구분하는 첫 연습이다.

### 산출물

- `AI 시스템 지도 v0`
- 구성 요소별 입력·출력·대표 실패 표
- 질문 백로그 초안

## 2회차 — 데이터·ML·LLM 맛보기

### 시간

2시간

### 학습 목표

- 데이터 기반 판단도 데이터와 평가 기준에 따라 틀릴 수 있음을 이해한다.
- 전통적인 ML 모델과 LLM의 입력·출력 차이를 구분한다.
- 학습과 추론이 다른 단계라는 사실을 안다.
- LLM 출력이 확률적이며 항상 사실을 보장하지 않는다는 것을 관찰한다.

### 진행

| 시간 | 활동 |
|---:|---|
| 25분 | Feature, Label, 학습, 추론, 평가의 전체 관계 |
| 25분 | 작은 게임 데이터와 분류 결과 관찰 |
| 25분 | Token, Embedding, Transformer, 다음 Token 예측 흐름 |
| 30분 | 동일 질문 반복, Temperature 변경, Context 유무 비교 |
| 15분 | 관찰 결과와 미래 연결 기록 |

### 가벼운 실습 A — 데이터 판단

20명 내외의 작은 사용자 데이터에서 다음 항목을 관찰한다.

```text
최근 접속 일수
평균 플레이 시간
매치 실패 횟수
결제 여부
이탈 여부
```

다음만 확인한다.

- 어떤 열이 Feature이고 어떤 열이 Label인가?
- 항상 다수 클래스를 선택하는 예측도 Accuracy가 높을 수 있는가?
- 미래의 정보를 Feature에 넣으면 왜 결과를 믿을 수 없는가?
- 모델 점수와 실제 업무 판단은 같은가?

모델을 처음부터 구현하거나 최적화하지 않는다.

### 가벼운 실습 B — LLM 출력 관찰

같은 질문으로 다음 조건을 비교한다.

```text
조건 1: 운영 문서 없이 질문
조건 2: 관련 운영 문서를 Context로 제공
조건 3: 관련 없는 문서를 함께 제공
조건 4: 동일 질문을 여러 번 실행
```

각 조건에서 다음을 기록한다.

- 답변이 달라졌는가?
- 근거가 제공된 내용과 일치하는가?
- 모르는 내용을 모른다고 표현하는가?
- 출력이 달라진 원인을 현재 수준에서 어떻게 추측하는가?

### 산출물

- `데이터 판단과 LLM 판단의 차이` 설명 1개
- LLM 조건별 출력 비교표
- 1~3주와 4~6주에 다시 확인할 질문

## 3회차 — LLM Application과 Agent 흐름 맛보기

### 시간

2시간

### 학습 목표

- LLM 응답과 애플리케이션 실행을 구분한다.
- Structured Output이 필요한 이유를 안다.
- LLM이 Tool을 직접 실행하는 것이 아님을 이해한다.
- Agent Loop에 종료 조건과 실행 제한이 필요하다는 것을 관찰한다.

### 진행

| 시간 | 활동 |
|---:|---|
| 25분 | 일반 텍스트 응답과 Structured Output 비교 |
| 25분 | Tool Schema, Tool Call, Tool Result 흐름 |
| 30분 | 한 번의 Agent Loop를 사람이 직접 역할극으로 실행 |
| 25분 | 잘못된 Tool 인자와 무한 반복 사례 관찰 |
| 15분 | Agent 실행 흐름 다이어그램 작성 |

### 가벼운 실습 A — Structured Output

같은 요청을 두 형태로 받아 비교한다.

```text
일반 텍스트:
"최근 실패율은 약 4%입니다."

구조화된 출력:
{
  "metric": "match_failure_rate",
  "period": "last_24_hours",
  "value": 0.04
}
```

다음 질문에 답한다.

- 프로그램에서 어떤 형태가 검증하기 쉬운가?
- 필드가 없거나 타입이 다르면 누가 거부해야 하는가?
- 구조화된 형식이면 값의 사실성도 자동으로 보장되는가?

### 가벼운 실습 B — Agent Loop 역할극

학습자, LLM, 애플리케이션, Tool의 역할을 분리해 다음 흐름을 종이나 메모로 실행한다.

```text
사용자 요청
→ LLM이 query_game_metrics Tool Call 생성
→ 애플리케이션이 인자 검증
→ Tool 실행
→ Tool Result를 LLM에 전달
→ LLM이 추가 검색 여부 판단
→ 최종 응답
```

그다음 다음 실패를 한 번씩 삽입한다.

- 존재하지 않는 Tool 이름
- 잘못된 기간 인자
- Tool timeout
- 같은 Tool의 반복 호출
- 종료 조건 부재

### 산출물

- Tool Calling Sequence Diagram
- 실패 사례별 책임 주체 표
- 7~9주와 10~11주에 다시 확인할 질문

## 4회차 — Retrieval·RAG·근거 맛보기

### 시간

2시간

### 학습 목표

- 검색과 답변 생성을 서로 다른 단계로 구분한다.
- 키워드 검색과 의미 검색이 서로 다른 결과를 낼 수 있음을 관찰한다.
- 검색된 문서가 틀리면 LLM 답변도 틀릴 수 있음을 이해한다.
- 인용이 있다는 사실만으로 답변이 정확하다고 판단하지 않는다.

### 진행

| 시간 | 활동 |
|---:|---|
| 20분 | Retrieval, RAG, Context, Citation의 관계 |
| 30분 | 키워드 검색과 의미 검색 결과 비교 |
| 25분 | 검색 결과를 LLM Context로 전달하는 흐름 관찰 |
| 25분 | 검색 실패, 충돌 문서, 잘못된 인용 사례 분석 |
| 20분 | 전체 시스템 지도에 Retrieval 경로 추가 |

### 가벼운 실습

게임 패치 노트와 장애 문서 몇 개를 대상으로 다음 질문을 검색한다.

```text
매치 서버 접속 실패가 증가했던 장애를 찾아줘.
```

다음 결과를 비교한다.

```text
키워드가 정확히 포함된 문서
표현은 다르지만 의미가 가까운 문서
주제는 비슷하지만 원인이 다른 문서
서로 충돌하는 두 문서
```

각 결과에 대해 다음을 기록한다.

- 검색 단계에서 정답 문서를 찾았는가?
- LLM이 검색 결과를 올바르게 사용했는가?
- 답변의 주장이 인용 문서에 실제로 존재하는가?
- 근거가 부족할 때 답변을 보류했는가?

### 산출물

- 키워드 검색과 의미 검색 비교표
- `검색 실패`와 `생성 실패`의 구분 설명
- 12~13주와 14~16주에 다시 확인할 질문

## 5회차 — 평가·안전·운영과 누적 진단

### 시간

2시간

### 학습 목표

- AI 시스템 품질이 모델 출력만으로 결정되지 않음을 이해한다.
- 정확성, 근거, Tool 성공, 지연, 비용을 분리해 관찰한다.
- Prompt Injection, 권한, 민감 데이터, 중복 실행을 대표 위험으로 인식한다.
- 전체 흐름에서 실패가 시작된 계층을 대략 분류한다.

### 진행

| 시간 | 활동 |
|---:|---|
| 25분 | 품질·안전·비용·지연의 기본 평가 축 |
| 25분 | Prompt Injection, 권한, 중복 실행, 데이터 노출 사례 |
| 30분 | 실패 시나리오의 발생 계층과 조사 순서 진단 |
| 30분 | 0주차 누적 미니 테스트 |
| 10분 | 시스템 지도 v1과 질문 백로그 정리 |

### 가벼운 실습 A — 한 요청의 Trace 읽기

다음 이벤트가 기록된 간단한 실행 로그를 시간순으로 배열하고 문제를 찾는다.

```text
request.started
retrieval.completed
tool.requested
tool.completed
model.completed
response.completed
```

다음 항목을 확인한다.

- 어느 단계가 가장 오래 걸렸는가?
- 같은 Tool이 중복 실행됐는가?
- 검색된 문서가 최종 답변에 사용됐는가?
- 권한 확인은 Tool 실행 전에 수행됐는가?
- 실패가 사용자에게 어떤 형태로 전달됐는가?

### 가벼운 실습 B — 위험 사례 분류

다음 사례를 데이터, Retrieval, LLM, Tool, Runtime, 권한·정책 중 하나 이상으로 분류한다.

- 오래된 운영 문서가 검색됨
- 문서 안의 지시문을 LLM이 사용자 명령처럼 따름
- read-only 사용자에게 변경 Tool이 노출됨
- timeout 후 재시도로 같은 작업이 두 번 실행됨
- 답변은 자연스럽지만 인용 문서에 없는 내용을 주장함
- 높은 품질의 답변이지만 비용과 지연이 허용 범위를 초과함

### 산출물

- 요청 Trace 분석 1개
- 위험 사례 분류표
- `AI 시스템 지도 v1`
- 정리된 질문 백로그
- 0주차 누적 미니 테스트 결과

## 누적 미니 테스트

미니 테스트는 합격 시험이 아니라 1~16주 학습 시간을 조정하기 위한 진단이다. AI의 힌트 없이 먼저 답하고, 답안을 제출한 뒤에만 AI 또는 정답 자료로 검토한다.

### 구성

| 유형 | 문항 수 | 확인 내용 |
|---|---:|---|
| 용어와 역할 | 6문항 | 각 구성 요소의 대략적인 책임 |
| 흐름 배열 | 4문항 | 데이터와 실행 순서 |
| 실패 분류 | 6문항 | 문제가 시작된 계층 |
| 미래 연결 | 4문항 | 어느 파트에서 다시 학습하는지 |

총 20문항으로 구성한다.

### 예시 문항

1. LLM과 Agent의 차이를 한 문장씩 설명하라.
2. Tool을 실제로 실행하는 주체는 누구인가?
3. 검색 결과에 정답 문서가 없을 때 어느 계층부터 조사해야 하는가?
4. Structured Output이 보장하는 것과 보장하지 않는 것을 구분하라.
5. 같은 요청에서 Tool이 두 번 실행됐다면 어떤 Runtime 개념이 필요한가?
6. Accuracy가 높아도 모델이 쓸모없을 수 있는 사례를 하나 제시하라.
7. Prompt Injection이 프롬프트 작성만으로 완전히 해결되지 않는 이유를 추측하라.
8. Token 사용량이 증가하면 어떤 운영 지표가 함께 영향을 받을 수 있는가?

### 결과 사용

- 16~20개: 예정대로 1주차 시작
- 12~15개: 예정대로 진행하되 1주차 복습 시간에 오답 재검토
- 0~11개: 1주차 첫 1시간에 전체 시스템 지도와 실패 분류를 다시 수행

점수는 학습 능력을 평가하지 않는다. 어떤 개념을 처음부터 더 자주 반복해야 하는지 확인하는 용도로만 사용한다.

## 미래 학습 연결표

| 0주차 첫 노출 | 다시 깊게 배우는 시점 | 그때의 학습 수준 |
|---|---:|---|
| Feature, Label, Baseline, 평가 지표 | 1~3주 | 손계산, 데이터 실험, 실패 판단 |
| Weight, Loss, Embedding, Token, LLM | 4~6주 | 작동 원리와 마이크로 실험 |
| Structured Output, Tool Calling, Agent Loop | 7~9주 | 최소 구현과 검증 |
| State, Event, Budget, Cancellation | 10~11주 | 실행 상태와 실패 제어 |
| Keyword Search, Vector Search, RAG, Citation | 12~13주 | 검색 비교와 근거 검증 |
| Eval, Injection, Trace, 권한, 비용 | 14~16주 | 종합 판단과 통제 실험 |

## 질문 백로그 형식

0주차에 궁금해진 내용을 즉시 깊게 조사하지 않고 다음 형식으로 남긴다.

```text
질문:
현재 추측:
관련된 전체 흐름 위치:
다시 학습할 주차:
그 주차에서 확인할 실험:
```

예:

```text
질문: Vector Search는 키워드가 없는 문장을 어떻게 찾는가?
현재 추측: 문장을 숫자 표현으로 바꾸고 가까운 것을 비교하는 것 같다.
관련된 전체 흐름 위치: Retrieval
다시 학습할 주차: 4~6주 Embedding, 12~13주 Retrieval
그 주차에서 확인할 실험: 같은 의미와 같은 단어가 각각 검색 결과에 미치는 영향 비교
```

## 0주차 완료 조건

다음 조건을 만족하면 상세 내용을 몰라도 1주차로 넘어간다.

- 전체 시스템 흐름을 자료 없이 대략적인 순서로 그릴 수 있다.
- Data, LLM, Retrieval, Tool, Agent Runtime, Evaluation의 역할을 한두 문장으로 말할 수 있다.
- 검색 실패와 답변 생성 실패를 개념적으로 구분할 수 있다.
- LLM이 Tool을 직접 실행하지 않는다는 것을 설명할 수 있다.
- 대표 실패 사례를 발생 계층과 연결할 수 있다.
- 모르는 내용을 질문 백로그에 기록하고 다시 학습할 주차를 표시했다.

완벽한 설명은 완료 조건이 아니다. 0주차의 결과는 완성된 지식이 아니라, 이후 반복 학습에서 갱신할 첫 번째 인지 지도다.

## 0주차에서 제외하는 내용

- 수학적 증명과 수식 유도
- ML 모델 튜닝
- 신경망 또는 Transformer 직접 구현
- Vector DB 구축과 최적화
- 완전한 Agent Runtime 구현
- LangChain, LangGraph 등 프레임워크 학습
- Production 배포
- Fine-tuning, LoRA, Multi-Agent

이 항목은 0주차에 궁금해져도 질문 백로그에만 남기고 현재 학습 범위를 확장하지 않는다.
